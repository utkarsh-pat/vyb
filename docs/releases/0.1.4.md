Release status: Verified internal debug candidate; production publication not approved

## Android changes

- Hardened Firebase Google credential validation and authenticated session
  bootstrap behavior.
- Reduced the startup anti-flash delay and added an explicit campus/session
  load failure state with retry.
- Prevented duplicate session, feed, story, vibe, and refresh work where the
  current lifecycle/state already owns an active request.
- Migrated launch-critical feature state collection to lifecycle-aware Compose
  collection.
- Added notification-href handoff for cold-start and warm activity intents,
  with allowlisted native destinations.
- Added Marketplace discovery controls: text search, categories, recent/price
  sorting, saved filtering, and meaningful filtered-empty states.
- Added image/video rendering for existing Marketplace sale listings and
  wanted/request records, including detail galleries.
- Expanded native search to People, Posts, Vibes and Market with UID-scoped,
  bounded discovery caching and partial-failure isolation.
- Added the Events host MVP core: create/edit, configuration preservation,
  registration review and approve/waitlist/reject actions.
- Replaced broken cookie-only Games URLs with Firebase-Bearer backend contracts
  for Connect and Queens daily/hint/submit, including tenant-bound signed
  sessions and server-side solution validation.
- Added community discovery, membership-safe chronological conversation,
  refresh and text send using the same backend contracts as web. Native
  community realtime remains blocked on a Firebase-Bearer socket-token
  endpoint.
- Added a native Scribble MVP with authenticated socket-token exchange,
  public/private lobby, room create/join, reconnect/rejoin, word and guess
  rounds, timer, score/member state, canvas stroke batching, and room controls.
- Added shared Home/Vibes social actions for like, save, Android share, repost,
  report, threaded replies, and owner edit/delete.
- Added comment like/unlike reactions with server-authoritative counts across
  Home and Vibes.
- Added foreground/data-only FCM rendering, notification channels and safe
  native deep-link intents.
- Migrated Android push registration and backend targeting from deprecated
  registration tokens to Firebase Installation IDs, with temporary legacy-token
  delivery compatibility.
- Hardened direct in-app updates with a Vyb-owned HTTPS allowlist, mandatory
  SHA-256 manifest metadata, filename sanitization, and pre-install checksum
  verification.
- Fixed chat identity storage across the full API 26-35 support range and
  disabled backup of device-bound encrypted account/key residue.
- Added tenant-scoped username availability, course/branch catalog selection,
  R2 avatar upload, and HTTPS-host-allowlisted social links to onboarding and
  profile flows.
- Updated the app update manifest defaults to Android `0.1.4` / version code
  `5`.

## Known blockers and incomplete parity

- Connect and Queens now have Bearer-authenticated backend contracts but require
  deployment and production device QA. Leaderboard/durable runs remain disabled
  until the Queens-aware Data Connect persistence contract exists.
- Scribble now has a native MVP and authenticated backend token route, but that
  backend change is not deployed. Multi-account gameplay and advanced
  settings/invites/reactions/eraser/share/result-posting remain release gaps.
- Community chat discovery, loading, send and navigation are implemented but
  still require multi-account device QA. Realtime is blocked until the backend
  exposes a Firebase-Bearer social socket-token contract.
- Marketplace displays existing remote media, but creation-time image
  attachments still require parity work and production device QA.
- Real FCM push taps have not yet been verified from both backgrounded and
  terminated app states.
- Authenticated emulator QA confirmed that at least one migrated Vibe record
  references a missing production media object (`404` from the canonical media
  route). The app now renders `Media unavailable` instead of a black/infinite
  loading surface, but the lost object requires backup recovery or record
  repair outside the client release.
- Compose UI tests for launch-critical screens are still missing.
- A stable release-signed direct APK and Play-ready signed AAB have not yet been
  produced. Debug-signed APKs are internal QA artifacts only.
- Play and direct-update build separation remains required before public Play
  distribution.

## Rollout decision

`0.1.4` is **not approved for rollout**. Complete the verification checklist,
deploy and device-test the new Games, Scribble, identity and media endpoints,
accept the community-chat status, and produce stable signed artifacts according to
`docs/process/ANDROID_RELEASE_RUNBOOK.md` before publishing update metadata or
starting a staged rollout.
